# Book Recommender

A Flask app that shows the 50 top-rated books and recommends similar books based on how readers rated them. It uses the [Book-Crossing dataset](https://github.com/ashwanidv100/Recommendation-System---Book-Crossing-Dataset).

## Run the app

Requires Python 3.12. Keep the virtual environment outside OneDrive or other synced folders, because they make it very slow.

```powershell
python -m venv $HOME\.virtualenvs\book-recommendation
& $HOME\.virtualenvs\book-recommendation\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements-dev.txt
python app.py
```

Then open http://127.0.0.1:5000. In production on Linux, run `gunicorn app:app`.

## Run the tests

```powershell
pytest
```

GitHub Actions runs the Python tests on Linux for pushes and pull requests.
To check the autocomplete timing and error handling, run `node --test tests/autocomplete.test.cjs`
with Node.js 20 or newer.

## Deployment notes

Search requests are limited to 16 KiB and book titles to 500 characters.
Autocomplete uses the same punctuation-insensitive matching as submitted searches.
Only load trusted `.pkl` files: Python pickle can execute code when loading.
Startup validates catalog coverage, unique search keys, and similarity dimensions and values.
Deploy `recommendation_bundle.pkl` with the application. It contains a schema version,
build timestamp, payload checksum, and title-order hash. Startup rejects corrupt or
misordered snapshots. The builder writes a temporary file and atomically replaces the
snapshot so a failed build preserves the previous version. Restart app workers after deployment.
Checksums detect corruption; they do not make untrusted pickle files safe to load.

## Rebuild the data

`recommendation_bundle.pkl` is generated by `build_artifacts.py`. Rebuild it when changing
the source data or build script. The four legacy root `.pkl` files are retained for
compatibility with older checkouts but are no longer loaded or updated by this app.

The script reads two input files from `data/source/`, which git ignores because they're large:

| File | Where to get it |
|---|---|
| `Ratings.csv` | [`BX-Book-Ratings.csv`](https://raw.githubusercontent.com/ashwanidv100/Recommendation-System---Book-Crossing-Dataset/master/BX-CSV-Dump/BX-Book-Ratings.csv), renamed |
| `books.pkl` | The original full file from the first commit. In Git Bash, run `git show 9c42670:books.pkl > data/source/books.pkl` |

Then run:

```powershell
python build_artifacts.py
```

Use the versions in `requirements.txt` for this, because the app may not be able to load pickle files written by a different pandas version.

## How it works

- **Top 50:** Ranks books with at least 50 explicit ratings by a weighted score, which pulls averages towards the overall mean so a few high votes can't top the list. Ratings of 0 mean "no explicit rating" in this dataset, so they're excluded.
- **Recommendations:** Uses cosine similarity between books, based on ratings from users with more than 200 ratings, for books with at least 50 ratings from those users.
- **Work identity:** Editions merge only when normalized title and author both agree.
  Different authors sharing a title get separate works and author-qualified search labels.
  Author aliases and spelling variants can still split editions into separate works.
- **Input quality:** Missing identifiers/titles and invalid ratings are excluded. Duplicate
  user/ISBN rows and user/work ratings use the maximum rating; each reader contributes
  once per work to popularity and activity thresholds.
- **Discovery:** Homepage cards link directly to results. Autocomplete shows author labels.
  Popular books outside the collaborative catalog remain searchable and show a clearly
  labeled selection of reader favorites instead of claiming similarity.
- **Covers:** Images come from [Open Library](https://openlibrary.org/dev/docs/api/covers), with a placeholder when a cover is missing.

## Measure recommendation quality

```powershell
python evaluate.py --seed 42 --output evaluation.json
```

The deterministic evaluation holds out one liked work (rating at least 8) per reader
with at least five liked works. All ratings for that reader/work are removed before
training and applying activity thresholds. Training likes seed an average item-similarity
ranking; previously seen works are excluded. Readers without usable seeds use the training
popularity baseline. The baseline ranks works by the number of training likes.

`evaluation.json` records Recall@9 and NDCG@9 for both methods, the seed, number of
readers, and target/seed coverage. Unavailable held-out works count as misses, rather
than disappearing from the denominator. With one relevant held-out work, Recall@9 is
the fraction of readers whose target appears in the first nine results.

This measures a multi-seed reader ranking built from the same item-similarity algorithm;
the website itself accepts one seed book. It is an offline diagnostic, not a guarantee
that a visitor will like a result. Compare changes using the same data and seed.
